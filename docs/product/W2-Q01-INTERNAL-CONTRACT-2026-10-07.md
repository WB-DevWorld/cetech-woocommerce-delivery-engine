## Behavior and boundary

Q01 makes the quote contract usable by internal application code. A quote has a server UUID, a separate opaque acceptance handle, exact owner/site/cart-session binding, canonical complete context and captured terms, immutable original header and an absolute300-second interval. Acceptance is a separate typed state transition; it preserves the original money, material/body digests and expiry. Changed context, owner, reference or original preconditions cannot silently reuse those terms. An accepted quote may later expire for new use while its accepted evidence remains intact.

The finite injected provider registry is empty by default. The only supported profile at this checkpoint is fixture_v1/version1; the provider used in tests is under tests/Support, and its synthetic native-looking receipts are explicitly fixture evidence rather than actual Woo capture. Nothing registers quote behavior in Plugin, checkout, REST, shipping rates, order snapshots or C03. There is no quote table, database writer, durable replay, admission budget, reference-safe cleanup or payment/stock/capacity reservation here. These are the Q02–Q06 boundaries.

The strict codecs refuse unknown format/profile/version, duplicate JSON keys including escaped aliases, extra/renamed members, non-string/exponent/negative/nonfinite money, malformed variation-parent membership and resource overflow. Authored absent dimensions normalize null/zero; unknown evidence stays distinct and refuses checkout acceptance. Original nested caller references are detached. Context canonicalization sorts semantic membership while retaining all material quantity, destination, service, source and policy facts.

Money is bounded nonnegative decimal text with declared currency/precision. Captured list, final, promotion, tax and total arithmetic is checked without calculating tariffs, taxes, conversion or rounding. Native per-rate/rounded tax and native charged/display money are distinct typed receipts. Missing tax/money or promotion facts are explicit unavailable/not-recorded states, which cannot become checkout-acceptable zero. Cost unavailable differs from known zero; route not-recorded differs from a recorded zero distance. The first context format permits checkout acceptance only when base/presentment/charged currency agree. Wider FX and economics remain separate.

Generic JSON serialization refuses private quote/context/terms/header/reference/money/owner/time/section carriers. Shopper and diagnostic outputs use independent finite allowlists; the shopper gets public labels, status, expiry and captured money, while diagnostics omit quote identity, money and private provenance. Admin disclosure checks exact current target and basic authority before a header-only loader. Cost, origin and rate each have separate typed loaders and rights checked before loading, after loading and before final disclosure. Callback exceptions produce finite sanitized errors. This is an internal projection seam, not a public quote-by-ID endpoint; the future native adopter must authorize current ownership before loading shopper facts.

Model stripping represents an eligible never-accepted body's terminal shape and preserves the header. It is explicitly not actual reference-safe retention authority. Read/clock uncertainty produces unavailable without mutating the quote. Neither read nor acceptance renews expiry. Durable original-envelope reconciliation, current physical source locks and retention/reference races are Q03's required proofs.
