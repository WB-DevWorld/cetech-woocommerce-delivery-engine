## Placement and recovery

The private confirmed cart envelope resolves the exact accepted quote, original owner, retained source, logical package/line membership, native money and tax material. Inert native shipping-rate attributes contain only quote ID, component handle and generation. They are presentation references; private readers establish authority independently. Cache-hit annotation preserves amounts and taxes and neither recalculates nor writes the session.

Classic stages at `woocommerce_checkout_order_created` priority `PHP_INT_MAX-1`, before C07's saved-order freeze. Store API stages only on final native POST at `woocommerce_store_api_checkout_order_processed` priority9, after native request synchronization and pending status but before the old priority10 writer and C07. GET, PATCH, PUT, totals and session restoration do not prepare, accept or seal placement.

The native order stager builds an exact logical-to-physical item mapping, installs the existing compatible delivery snapshot with Q05's strict quote envelope, and reloads saved physical evidence. Product, shipping and tax items, money, addresses, keys and every mandatory quote member are fenced. The pinned Classic handler reloads the native order between creation and its processed hook; that handoff requires exact original native facts and saved packet/context verification before C07 can freeze the new object. HPOS `tax_amount` and CPT `_order_tax` represent cart tax excluding shipping; native total tax additionally includes shipping. Decimal comparison normalizes only canonical trailing zeroes. Fees, coupons, ambiguous mapping, missing or duplicate mandatory metadata and unsupported native facts refuse placement.

The private placement lifecycle is prepared revision1, verified prepared revision2, sealed revision3. `delivery_quote.verify_binding@1` records the exact saved packet/context digests in the original deterministic placement namespace. `delivery_quote.seal@2` requires the same C07 revision, raw local binding, accepted quote, saved physical evidence and current owned source fences. The final placement receipt must be acknowledged and its connection retired before C07 returns allowed to the native gateway or free-order branch. The retained internal seal@1 contract remains versioned separately.

Prepared recovery writes only missing original protected bytes at revision1; existing bytes must match exactly. Verified and sealed history is verify-only. Unknown acknowledgement is not success. Reconciliation resolves the original receipt and physical effects; a failed or retired SQL owner cannot open an implicit replacement to record a rejection or payment effect. Linked verification receipts prevent physical binding rollback from revision2 to revision1. A known terminal no-effect final rejection can release only its native pointer after exact original linked receipts, prepared2 and saved physical bytes pass an acknowledged read/rollback/retirement. A different explicitly reviewed and confirmed quote of the same owner then creates a new intent. Old order, binding, quote and rejection history remain unchanged; missing, pending, malformed or unknown outcomes cannot grant that disposition.

Classic resume interception precedes Woo's pending-order item deletion. Native pending/failed orders without quote ownership can rebuild item rows using logical membership and newly verified physical IDs. Protected prepared histories retain their original binding and item identities. Sealed same-envelope retries recover the original order and binding; changed accepted intent uses a new order and preserves old history. Native session/cookie/nonce or exact-order authorization precedes private loading. Store API's mutable draft pointer is acknowledged and detached before sealing, with a separate private original payment continuation. Later GET/PATCH cannot mutate the sealed order. Cross-route retries use the original stored route and refuse a changed native request payload.

Order-pay resolves the authorized original native order independently of a live cart. Fresh admission checks the original saved source and current C07 policy. Expired or changed admission returns a native safe checkout notice and303 termination; genuinely absent quote ownership preserves the legacy path. An acknowledged payment continuation must preserve protected bytes and exact native order facts through the subsequent native payment-method save and before the gateway. Later policy changes do not retroactively replace that acknowledged admission.

The full actual session bytes and native object facts still form a separate exact current physical guard. Enablement requires the complete Classic chain, Blocks flag, shipping/source/readers/schema9/C03 readiness. A stale admin revision cannot replace a newer decision.
