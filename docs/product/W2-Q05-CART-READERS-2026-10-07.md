## One admission before preparation

The early preparation command consists of current owner/site/key epoch, a bounded purpose-keyed cart draft digest, original request token and the finite provider/profile tuple. The draft reads already loaded native primitives; it cannot look up products, resolve source rules, calculate tax, call a provider or insert a C03 reservation. Authenticated native transport and current owner are required before admission lookup and before disclosure/effect.

The gate uses existing schema9 `delivery_quote.issue` slots and the same eventual issue namespace. It locks current C07 control, site-minute, session-minute and exact original admission slot on one owned connection. It charges one complete cart attempt,20/session/minute and200/site/minute, independent of package count. Acknowledged completion and connection retirement yield a private one-use60-second preparation capability. Original live uncertain admission can reconcile; a fresh process cannot reconstruct that capability. Lease expiry, pause, identity change and minute-counter cleanup cannot renew or resurrect it. Known pre-C03 preparation failure terminates the exact original lease without refund; an uncertain C03 write cannot be cancelled by that path.

A fresh custom cart request need not have calculated shipping packages. The cheap draft binds raw protected per-line selections, customer context, native destination and currency; transient packages and automatic chosen-rate materialization are excluded. After admission, the native builder calculates native totals, persists the normal native cart session before capture, derives genuine bounded source/inventory/destination/native tax/money facts and invokes the retained Q04 final preparation. The final canonical issue intent is bound once locally to the preparation lease. Its immutable earlier intent remains in the admission row; the final C03 profile verifies both that stored digest and the exact full final command. Admitted issue skips a second quota charge while preserving the existing same-owner current source/control locks and atomic quote/event/completion/consumed-slot unit. Existing internal `issue()` remains supported.

## Server references and explicit review

The server resolves the owner and draft. Browser generation and UUID review token are concurrency/replay inputs, never customer, price, owner, material or acceptance authority. Only explicit refresh prepares/issues; only explicit confirm accepts; retry uses the original staged envelope. Cart reads, totals, StoreAPI GET/PATCH and session restoration do not accept or place a quote.

Private server references use a purpose-bound32-character owner-HMAC key in an auxiliary row of the existing WooCommerce sessions table. Exact native table/site/owner/current authority and physical generation CAS protect it. Native `save_data` writes its ordinary customer row and cannot erase this auxiliary row or publish an older quote generation. Login/logout/auth-session rotation changes the quote owner. Native WooCommerce may share a persisted customer cart between two logins of one user; quote ownership still includes their distinct actual WordPress auth-session tokens. This checkpoint does not claim that native WooCommerce creates independent customer-row carts.

Before a possible durable issue commit, the store stages its UUID/private acceptance reference/header and exact original early/final envelope. The protected original envelope may include the strictly bounded original `QuoteContext` needed to reproduce its canonical intent; it contains keyed destination facts and finite captured digests, not a raw address, arbitrary provider body, `QuoteTerms`, cached quote body, guard object or shopper DTO. A failed or late publication preserves durable facts and permits original-envelope reconciliation without a second capture, write or audit. Uncertain work cannot be replaced by a refresh under a new token.

Ordinary reads check the original owned envelope and current C07 control before reconstructing fresh bounded evidence. They restore only an existing native calculation with exact package hash, existing shipping-version transient, chosen methods, bounded native rate objects and matching totals. Missing or changed caches refuse; this path does not calculate totals, call the pricing engine or write a native session/transient. Native hook policy is checked before package construction, and raw rate fields avoid filtered getters. Final owned source/native guards still recheck owner, material, absolute expiry and C07. A cached result cannot provide authority or extend expiry. Shopper/diagnostic fields are explicit allowlists; private session envelopes and protected packet references have no generic serialization. Existing exact-scope administrator projection and separate sensitive permissions remain.

Classic wc-ajax POST uses a purpose-specific real native nonce. StoreAPI uses native cookie/session plus its real Nonce and explicit `cart/extensions` mutation callback. Both expose the same detached review DTO. Blocks uses actual `extensionCartUpdate`; refreshed money must be visible before a separate confirmation action. Expiry/change preserves the shopper's selections and offers explicit refresh/review. Unknown/missing/paused evidence cannot produce an acceptable quote or a fabricated zero price. Native checkout writer enforcement is Q06.

## Reader before writer

Protected `delivery_quote` format1 is separate from C05 `quote_policy.reference`. Its exact keys are `format`, `quote_id`, `profile`, `issued_at`, `expires_at`, `accepted_at`, `body_digest`, `material_digest`, `placement_id`, `context_digest`, `money_receipt` and `provenance_receipt`. The supported profile is `legacy_fixed_base_v1`/1. Native money/tax/no-promotion receipts have strict nested codecs; arbitrary provider JSON and new unknown keys are refused. The packet is bounded64KiB/depth16 with finite groups, exact UUID/digest/timestamp shapes and captured currency/precision. Recognition of this captured shape never proves sealed placement or payment; Q06 must resolve the exact private binding and original context digest.

The order/item marker `_cetech_de_delivery_quote_format` uses native `meta_exists` plus bounded native raw metadata inspection, because WooCommerce filters physical null metadata out of that method. Null or empty present metadata is not absence. Marker presence or the reserved member requires the known packet before legacy fallback. Unknown format, malformed mandatory receipt, missing packet and incompatible line/order packet refuse. A quote-owned order's managed lines require matching identities/receipt digests. Genuine absence preserves existing V1/V2/C05 raw historical bytes and facts. Reads never backfill metadata, reconstruct current pricing, or overload an old reference. Historical/customer projections use captured money and strip protected identities/provenance; diagnostics remain finite.

Compiled reader support is an exact format/profile capability, explicitly `reader_only`. It is not storage readiness, placement readiness or writer activation.
