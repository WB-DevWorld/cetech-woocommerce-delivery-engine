## Resulting behavior

The control pauses new Delivery Engine delivery and pickup checkout admissions, including payment of existing unpaid managed orders. It leaves paid-order callbacks and existing authorized shipment work available. Pure WooCommerce commerce continues only after authoritative ownership checks establish that it is unmanaged. Disabled storefront flags, failed resolution, malformed owned markers, or unavailable options do not establish unmanaged ownership.

The option `cetech_de_checkout_control_v1` is a distinct preserved control, separate from the existing 23 feature flags. A checked current absence means the legacy enabled view at revision 1 without a write. The first changed transition writes revision 2. State, sanitized material event and operation completion are accepted through the existing C03 transaction. Same-state requests complete as `not_applicable` without initializing an absent option or adding a material event. Replays retain the original completion and do not restore an older state over a newer opposite transition. Unsent commits and lost acknowledgements retain their different outcomes.

Physical option reads are authoritative. Publication invalidates only the named option, `alloptions` and `notoptions`; it never republishes old bytes. A failed publication is pending, while the accepted database effects remain accepted. C07 uses the existing operation stores and schema target 8. It adds no table or migration and does not expand the C06 managed-cache write namespace.

Early cart/product guards are usability checks, not admission stamps. Final Classic and Store API processed-order hooks run at `PHP_INT_MAX`. Final admission classifies actual order items, validates current coherent eligibility and quote equality outside the control lock, then confirms the same enabled revision under the current lock with unchanged request facts. The owner releases and retires before a process-local stamp can exist. No stamp or new admission metadata is written to an order or snapshot. An already admitted payment may finish after a later pause.

The request-local latch captures possible ownership before session restoration or reconciliation discards markers and binds Classic-created order items. A verified cart removal clears that removed line's latch. An emptied Classic cart does not erase ownership of the actual order. Malformed package, contents-container and line inputs produce an explicit derived-package refusal and unresolved latch, so their disappearance cannot yield native final admission. Actual cart and order data are not rewritten by this refusal.

New product choices, matching/variation choices, capture, reselection and managed quote production refuse during suspension or unavailable control. Existing customer address drafts remain editable using the same server-observed choice and offer/pickup identity; this path makes no new choice validation or quote. A different submitted choice is refused. Existing apply-to-all paths cannot accept a new choice while the shared validator refuses.

Managed package metadata includes the current state and revision in WooCommerce's package hash. Suspended pickup does not become a fabricated zero rate. Managed and unresolved packages cannot fall back to Flat Rate or native Local Pickup, including when old runtime flags are inactive. A mixed package retains a separate verified native residual where analysis is complete.

The unpaid order-pay hook is outside WooCommerce's gateway exception boundary. Refusal therefore adds a safe Woo notice, obtains the checkout URL from the server, issues a validated safe 303 redirect and terminates. Failure to establish that redirect terminates with a safe 503 response. Returning normally or relying on an ordinary exception is not the refusal implementation. After resume, payment requires fresh quote equality to stored amounts, currency and tax facts; C07 neither reprices the order nor reconstructs missing historical facts.

Shopper refusals use the actual finite `EmergencyAdmissionResult` through `EmergencyControlProjection::for_shopper`, including a safe correlation reference. Authorized settings and diagnostics recheck current authority before loading and disclosure. Generic serialization of internal state, admission evidence or diagnostics refuses. Operator identity, original option bytes, request tokens, private pricing dimensions and raw storage exceptions are excluded from shopper output.

## Limits and implementation locations

- Physical control records: at most 2,048 bytes, strict flat typed format/version/site/state/reason/revision/actor/time validation. The original bytes remain an exact opened precondition.
- Ownership and final evidence: at most 200 lines and 200 packages; overflow refuses rather than granting a partial admission.
- Native options: verified current site/prefix, InnoDB, full unique option-name identity and supported standard WordPress route. Admission requires REPEATABLE READ and the existing two-second lock-wait bound. Unknown reads, release and retirement refuse.
- Activation: deterministic current-site all-or-none. There is no percentage or cohort adopter.
- Impact: bounded observed estimates, with explicit incompleteness; no exhaustive address/cart scan.
- Schema target remains 8. Existing V1/V2 snapshots, C03/C04/COR-007 history and all 32 declared domain storage families keep their existing owners and retention policy.

Core files are `src/Domain/EmergencyControl/EmergencyControlState.php`, `EmergencyControlReadResult.php`, `EmergencyControlDiagnostics.php`; `src/Infrastructure/Persistence/EmergencyControlStore.php`; and `src/Application/EmergencyControl/{EmergencyControlCommand,EmergencyControlOperationProfile,EmergencyControlService,EmergencyOwnershipClassifier,EmergencyOwnershipLatch,EmergencyCheckoutFacts,EmergencyCheckoutQuoteValidator,EmergencyCheckoutAdmissionService,EmergencyAdmissionResult,EmergencyControlProjection}.php`. The read/quote interfaces make the dependencies explicit.

`src/Integrations/EmergencyControl/{EmergencyControlRuntime,EmergencyCheckoutHooks,EmergencyControlResponse}.php` supplies the shared Woo adapters. Existing selector, capture, reconciliation, reselection, shipping, draft-editor and checkout constructors take the optional shared runtime; `src/Bootstrap/Plugin.php` supplies the production singleton. The always-live hooks include session-latch capture, final add-cart-item-data guarding, verified removal/restoration, actual Classic order-line binding, early Classic/Store API checks, final Classic/Store API admission, order-pay termination and managed package/rate guards. They register independently of the old flags.

Administrative handling is `src/Presentation/Admin/EmergencyControlSettings.php::{handle_actions,render,parse_form}` with the existing `AdminActionHandler` and `AdminPageAccess`. `SystemStatusPage::diagnostic_report_text` uses the authorized diagnostics projection. `DataLifecycleManifest` preserves the distinct option.
