## Resulting behavior

The compiled registry declares 123 exact storage classes, including all32 durable domain stores. Ordinary cleanup and explicit uninstall preserve their rows, schema marker, authored settings, feature flags, material audit, scoped and generic completion history, rule versions, bulk/pack evidence and protected Woo facts. No table is dropped. Unknown declarations, ownership, formats and reference predicates do not grant disposal.

The sole adopted cache is StorefrontGeographyEndpoint's existing children/search/postcode response cache. Its three call sites retain the current queries, authentication, nonce, rate limiter, response shape and120-second maximum. The new per-site typed option envelope includes locale, opaque promoted-pack revision, purpose-bound HMAC identity, physical row identity and generation. Search request tokens are omitted from storage and the current token is attached to a cached response. Oversized/unknown rows miss and remain preserved. Observation anchors expiry; reading and delayed publication do not slide it. SQL current-lock reads validate advisory object-cache hits, so delayed older entries cannot override a newer generation or its bytes. These tickets establish current presence/absence, not an everlasting insert/delete history.

The options adapter uses C03's fresh native transaction owner, actual current WordPress options route, InnoDB and full primary/unique identities. Cleanup fixes one native UTC cutoff and MAX option ID, walks candidates in ascending1000-ID windows with a201-row probe, and inspects at most200/removes at most50 in one2-second soft batch. Candidate disappearance, renewal and malformed ownership advance the cursor without false early completion. Exact deletion and coordinator revision/counts commit together. Positively unsent commit with acknowledged rollback is retryable; lost acknowledgement/failed retirement requires fresh current-lock reconciliation before another effect. Dry-run rolls back its read unit and creates no coordinator, audit, ledger or schedule.

AS dispatch is exact hook/group/current site/run/checkpoint, one acknowledged batch per tick, positive pending action IDs,1-second continuation and300-second maintenance. A late completed action must still match the locked previous coordinator before a new run starts. Public AS3.9.2 cancellation does not guard pending status atomically. Deactivation therefore stops this site's exact registered C06 handlers and retains all AS rows; the bounded observation reports `cancellation_supported=false`. Reactivation resumes validated progress. This implements the approved stop behavior without claiming unsafe pending cancellation or queue draining.

Both uninstall entry points call the same manifest and executor. The standalone root path loads a fixed reviewed own-source closure, without Composer, WooCommerce or arbitrary class loading. Explicit intent accepts only integer1/string1 and is rechecked physically. At most one owned cache batch executes. Incomplete/unknown/unsupported work retains intent. Only acknowledged native transaction publication of the exact roles option minus18 plugin capabilities, preserved unrelated/direct user grants, activation-notice removal, marker verification and acknowledged intermediate status permit intent consumption. The role control unit respects native pre-update filters, locks and compares physical ID/value/autoload before a fixed-key CAS update, then refreshes native roles only after acknowledged commit/retirement. A reproduced cached-array overwrite of a concurrently committed foreign grant now refuses without overwriting the newer row. Default uninstall preserves everything; absent helper preserves intent. Merchant copy accurately describes cache/role removal and business-record preservation.
